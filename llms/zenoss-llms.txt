> AIOps and full-stack IT infrastructure observability. Zenoss was acquired by Virtana in May 2025
> and is sold as Virtana Service Observability; zenoss.com now redirects to
> virtana.com/service-observability. The developer surface is unchanged and still branded Zenoss:
> a /v1 REST API, first-party proto3/gRPC contracts, and the long-standing JSON router API for
> Collection Zones and on-premises Resource Manager.

## Authentication

All /v1 services take a long-lived key in the `zenoss-api-key` request header. Keys are issued per
API Client from ADMIN > API Clients in three types — User Management API, User API, and Streaming
Data Ingest API — and the type decides which services the key can call. Keys cannot be retrieved
after creation and do not expire; deleting a key denies access within 60 seconds. The legacy router
API uses a differently named `z-api-key` header (Collection Zone) or HTTP Basic (Resource Manager).
There is no OAuth 2.0 and no OpenID Connect on any API surface.

- [API client keys](https://docs.zenoss.io/admin/clients/zenoss-api.html)
- [Collection Zone keys](https://docs.zenoss.io/admin/clients/cz-api.html)

## Machine-readable contracts

No OpenAPI or Swagger document is published — /openapi.json, /openapi.yaml, /swagger.json,
/api-docs, /docs and /redoc all 404 on both the API host and the docs host. The contracts that DO
exist are proto3:

- [zenoss-protobufs](https://github.com/zenoss/zenoss-protobufs) — DataReceiverService,
  DataRegistryService, CredentialManagement, CollectionConfigService. Go module v1.5.5 (2026-07-27).

## Legacy router API

[Zenoss API for Collection Zone and Resource Manager](https://docs.zenoss.com/api/background.html) —
61 documented routers reached by HTTP POST to /zport/dmd/<router> with a
{"action","method","data","tid"} envelope. Covers devices, events, event classes, triggers,
templates, reports, jobs, users, LDAP, SAML IdP, licensing, ZenPacks, impact, and vendor surfaces
(AWS, Azure, vSphere, Hyper-V, OpenStack, Cisco UCS, EMC Isilon, SMI-S). Zenoss states some of this
will be replaced by the /v1 services over time.

## Conventions

- JSON over HTTPS. Non-CRUD operations use Google AIP colon suffixes — :search, :count, :batchGet,
  :list, :deleteBulk, :test.
- Cursor pagination: pageInput{pageSize,cursor,direction} in, pageInfo{count,totalCount,hasNext,
  startCursor,endCursor} out. The credentials service uses nextPageToken instead.
- Errors return {"code": <int>, "message": "<text>"} — the gRPC status shape, not RFC 9457.
- No idempotency key on any write. No documented rate limits, no 429, no rate-limit headers.

## Events out

Actions rules deliver JSON to webhook, Slack, Microsoft 365, PagerDuty, ServiceNow, Zoom and email
destinations. [Webhook payload example](https://docs.zenoss.io/actions/reference/webhook.html).
No AsyncAPI, no webhook signature scheme, no documented retries.

## OpenTelemetry

[OTLP ingestion](https://docs.zenoss.io/streaming/open-telemetry.html) — exporter type OTLP,
endpoint https://api.zenoss.io:443, header zenoss-api-key. Sum, gauge and histogram metrics.
